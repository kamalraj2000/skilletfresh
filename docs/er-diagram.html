Structural notes

The core chain

User → Profile → Plan → PlannedMeal → MealLog. A profile gets one plan per week (unique(profileId, weekStart)), one meal per day (unique(planId, dayIndex)), and at most one log per planned meal — that log is the North Star instrument.

Recipe is the shared corpus

Referenced from planned meals, the swap pool (PlanAlternate), and replan entries. It doubles as the cached recipe corpus the agent draws from — parsedVia records whether a row came from seed data, JSON-LD scraping, or LLM extraction.

Cascade boundaries

Deleting a Plan cascades through PlannedMeal, PlanAlternate, ShoppingList (→ ShoppingItem), and ReplanProposal (→ ReplanEntry). MealLog cascades from PlannedMeal. Recipe, Profile, and User never cascade.

Dashed wires are intentional decoupling

AgentJob and AgentRunLog store profileId (and jobId) as plain strings with no foreign-key relations — the event bus and telemetry layer sit deliberately outside the relational graph.
